# MSSS — Market Scoping & Survey System

> MSSS is a full-stack system for publishing market-scoping / procurement announcements, collecting supplier responses, and managing users and notifications.

**Repository structure**
- **Backend/**: Express API, Postgres (Supabase-compatible) connection, email & storage utils, migrations, and scripts.
- **Frontend/**: Vite + React frontend (Ant Design) for admin/buyer/supplier UX.

**Quick start (local)**
1. Backend
   - Install dependencies and start the API:

     cd Backend
     npm install
     npm run dev

   - The backend expects a Postgres-style `DATABASE_URL` in environment variables.

2. Frontend
   - Install and start the frontend dev server:

     cd Frontend
     npm install
     npm run dev

   - The frontend runs on Vite (default port 5173). Configure the backend origin via `FRONTEND_ORIGIN` for CORS if needed.

**Important environment variables (Backend)**
- `DATABASE_URL` — required Postgres connection string (used by `Backend/db.js`).
- `JWT_SECRET` — secret for signing/verifying JWTs.
- `SYSTEM_EMAIL` — address used to send system emails.
- `SYSTEM_EMAIL_APP_PASSWORD` — app password (SMTP) for `SYSTEM_EMAIL`.
- `AZURE_STORAGE_CONNECTION_STRING` — optional; used for Azure Blob uploads/downloads.
- `SUPABASE_URL` and `SUPABASE_SERVICE_ROLE_KEY` — optional admin flows when using Supabase.
- `FRONTEND_ORIGIN` — optional; add deployed frontend origin for CORS.
- `CORS_ALLOW_CREDENTIALS` — set to `true` to allow credentials in CORS.
- `PORT` or `APP_PORT` — port to run the backend (defaults to `3000`).
- `VERCEL` — set in Vercel serverless deployments; server behaves accordingly.

Place environment variables in a local `.env` file inside `Backend/` (not committed).

**Scripts & tools**
- `Backend/package.json` scripts:
  - `npm run dev` — start with `nodemon` for local development.
  - `npm start` — start `node Server.js`.
- `Frontend/package.json` scripts:
  - `npm run dev` — start Vite dev server.
  - `npm run build` — build production assets.

**Database & migrations**
- Migrations are located in `Backend/migrations/` — run them using your preferred migration tool (the repo contains SQL-style migration files).
- Use `resetPassword.js` (in `Backend/`) to reset a user's password from the command line. Example:

  cd Backend
  node resetPassword.js --email user@example.com --password NewPass123

**Email & storage**
- Email sending uses `nodemailer` and expects `SYSTEM_EMAIL` and `SYSTEM_EMAIL_APP_PASSWORD`.
- File storage supports Azure Blob (via `AZURE_STORAGE_CONNECTION_STRING`) and Supabase uploads.

**Docker / Deployment**
- A `Backend/Dockerfile` exists for containerizing the API; `docker-compose.yml` at repo root can be used for multi-container setups when present.
- The backend contains Vercel-aware code paths (`VERCEL` env) for serverless deployments.
